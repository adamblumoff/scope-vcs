Source control with boundaries

Open source shouldn't be all or nothing.

Scope keeps public and private code in one Git repository. A public clone contains only the files you choose to share. Contributors submit requests against that view, and accepted work returns to the same history.

Pre-alpha. The core collaboration loop works today.

How Scope works

One project. The boundary does the work.

The repository remains authoritative. Scope derives each view from its visibility rules and routes outside work back through a request.

How work comes back

Work stays private until it asks for attention.

A request starts as a private Draft. Opening it places the work in the maintainer queue without freezing discussion or revisions. The maintainer then merges or closes it.
