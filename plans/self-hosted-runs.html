Scope VCS · implementation plan · self-hosted runs

Commit here. Execute on the machine that fits.

Add repository-defined workflows and a durable remote-runner protocol to Scope. The same binary remains a normal CLI on a developer machine and becomes a persistent execution daemon on any Linux box. Scope coordinates source, dispatch, logs, and status; users supply the compute.

Recommended V1: Linux/amd64 + Docker, one persistent Scope daemon per runner machine, repository allowlists, outbound HTTPS only, manual and push triggers, one disposable container per job, and small sequential workflows stored in .scope/runs/*.yml. No hosted compute, secrets, shared caches, marketplace actions, or automatic execution of untrusted public contributions.

01

V1 product decisions

These choices keep setup small without weakening the boundaries that protect Scope infrastructure and repository privacy.

Execution target

A runner is a named remote machine registered with Scope. Manual runs can select one with --runner linux-box; automatic runs use runs-on from repository YAML.

Installation

The existing scope binary installs a user-level systemd service. Registration happens once; the daemon reconnects after reboots and accepts jobs indefinitely.

Supported host

Linux/amd64 with Docker. The daemon persists, but every job receives a fresh container and workspace that are destroyed on completion.

Runner scope

A machine identity may be attached to several repositories through an explicit allowlist. Each attachment is independently revocable.

Workflow language

One YAML file defines one container job with sequential named steps, timeout, trigger, image, and runner selection. No general expression engine or action marketplace.

Source behavior

Every run executes an exact committed revision. A manual run may upload an unpublished, immutable snapshot without moving main; dirty working-tree changes never run implicitly.

Trust boundary

V1 is maintainer-triggered and secretless. Public-contribution automation waits for explicit approval and a stronger untrusted execution profile in a later phase.

Network

Jobs receive normal outbound internet access for dependency installation, but no Docker socket, privileged mode, host filesystem, database credential, object-store key, or reusable repository token.

Image pinning

V1 accepts public image tags for easy setup. The first claimant resolves and compare-and-set pins the registry digest before execution; every later attempt reuses that digest.

Retry

A lease lost before execution may requeue automatically. Once a container starts, runner loss produces a terminal Lost attempt and requires an explicit rerun.

02

Scope is the rendezvous point

Developer machines and runner machines never need a direct route. Both independently connect to Scope over HTTPS.

03

The repository owns the workflow

Workflow definitions are committed control files. Local CLI metadata moves out of .scope so the directory can become a tracked repository surface.

.scope/runs/test.yml
name: Test

on:
  manual: true
  push:
    branches:
      - main

runs-on: any

container:
  image: rust:1.90

timeout: 20m

steps:
  - name: Format
    run: cargo fmt --check

  - name: Test
    run: cargo test --workspace
Identity

The path stem is stable: test.yml is invoked as scope run test.

Routing

runs-on: any selects an idle attached runner. A concrete name such as linux-box pins automatic runs.

Push scope

V1 accepts only main push triggers because Scope does not yet expose generic branch semantics. Any other branch selector is a validation error.

Manual override

scope run test --runner build-vps overrides routing for one invocation without changing Git.

Authority

Scope parses and snapshots YAML. The runner receives a compiled job specification and never decides triggers or authorization.

Destructive repository-state reset

Precise control policy

Allow only tracked .scope/runs/{valid-name}.yml|yaml. Keep repository config and workflow control paths private/unpublishable, reject unknown .scope/*, and update import validation, projection, visibility, review-tree, dirty-tree, clone, init, and push tests together.

05

Manual run: local intent, remote execution

An agent can execute a committed work-in-progress revision remotely without pushing it onto main.

Developer or agent machine
$ scope run test --runner linux-box

Uploading unpublished snapshot for 4f837e1
Queued Test on linux-box

✓ Checkout       1.2s
✓ Format         2.1s
✓ Test          14.3s

Run succeeded · 4f837e1 · linux-box

Ctrl-C detaches from the log stream; it does not silently kill remote work. Cancellation is explicit with scope run cancel <run-id>.

06

Push trigger: server-authoritative dispatch

The server evaluates committed workflow definitions after the repository head is accepted. The pushing client does not decide which automatic jobs exist.

scope push returns after Git acceptance with the pinned change version. scope push --wait then queries trigger evaluation by that identity and follows the resulting runs; receive-pack does not pretend async run IDs already exist.

07

A run pins content, audience, and workflow

A lone SHA is insufficient in Scope because the public and private repository views can materialize different Git histories.

Manual default

If Scope already knows the commit, resolve the selected accepted revision. Otherwise upload an EphemeralGitSnapshot that is private-only in V1. Resolve workflow YAML from the same exact source.

Push default

The acceptance transaction/outbox carries change_version, manifest ref, and head OID. Trigger evaluation reads YAML and source from that pinned head—not whatever main points to when the async worker wakes up.

Historical cutoff

Materialize the currently authorized audience projection only through the selected logical/projected point and target OID. A private-only logical revision may have no public selector and must fail closed.

Public contributions

Do not auto-run in V1. The future model uses a trusted base workflow, a public target snapshot, explicit maintainer approval, no secrets, and a separate untrusted runner policy.

Run and attempt lifecycle

09

Thin protocol, narrow credentials

The runner never receives database credentials, object-store keys, a human CLI session, or a reusable repository token.

POST /runners/register
Exchange one-use device authorization.

Creates machine identity, returns a random bearer secret once, stores only its hash, and discards the human session.

POST /runners/{id}/poll
Long-poll for matching work.

Authenticated by machine identity; response is empty or contains a lease offer.

POST /runs/{id}/claim
Atomically claim an attempt.

Checks runner grant, desired runner, version, active attempt, and lease state; returns compiled job and short-lived attempt token.

POST /attempts/{id}/heartbeat
Extend active lease.

Rejects stale attempt number, revoked runner, expired token, or terminal run.

GET /attempts/{id}/source
Download the pinned snapshot.

Attempt token can read only the content-addressed source object selected for this run.

POST /attempts/{id}/logs
Append bounded log chunks.

Monotonic sequence numbers make retries idempotent; server strips unsafe terminal control sequences.

GET /runs/{id}/events
Watch with a resumable cursor.

SSE emits bounded log/status events, supports reconnect from the last sequence, and applies server-side backpressure.

POST /attempts/{id}/complete
CAS terminal result.

Only the current active attempt may complete; stale or duplicated completion is harmless.

POST /runs/{id}/cancel
Request cancellation.

Queued work cancels immediately. Leased/running work becomes Canceled only after runner acknowledgement; disappearance remains Lost with cancellation requested.

Machine credential

Long-lived, hashed server-side, rotatable, and revocable. May poll, claim eligible jobs, report version, and heartbeat. Cannot fetch repository content on its own.

Attempt token

Short-lived and bound to one runner, run, attempt number, source snapshot, and log/status endpoints.

Job specification

Contains resolved source, ordered steps, timeout, supported resource limits, environment metadata, and no server-side secret material. The first claimant CAS-pins the public image digest before start.

Recovery and retention

Containers use deterministic attempt names. On daemon restart, reattach if still running; otherwise kill any orphan and report Lost. Source/log object references are retained with the run, then garbage-collected by explicit policy.

Expected ownership map

Exact paths may change during implementation, but domain ownership and the separation between trusted infrastructure work and untrusted job execution should not.

Run domaincrates/scope-domain/src/runs/
Own workflow revisions, source snapshot identity, triggers, runner selection, run/attempt states, allowed transitions, cancellation, retry policy, and required side effects. Keep transport, SQL, Docker, and YAML parsing outside the core behavior modules.
Persistencecrates/scope-postgres/src/db/runs/ · runners/ · schema.sql
Store workflows, revisions, runners, repository grants, runs, attempts, leases, log object references, and idempotency keys. Claim with row locking and compare-and-set completion. Keep internal projection outbox jobs separate.
Wire contractcrates/scope-api-contract/src/runs.rs · runners.rs · routes.rs
Define CLI/user APIs separately from the machine protocol. Export public run/status types to the web client; never expose runner credential or object-store representation.
API adaptersapi/src/http/runs.rs · runners.rs · runner_protocol.rs
Authenticate, translate, call domain behavior, persist, and stream. Add push-completion outbox creation after authoritative Git state commits. Keep dispatch rules out of handlers.
Source snapshotscrates/scope-git · api/src/git/run_snapshots.rs
Materialize immutable private/public Git inputs and generate bounded bundles. Reuse content-addressed object storage without giving runner machines direct bucket credentials.
CLI and daemoncli/src/runner/ · cli/src/run/ · cli/src/bin/scope.rs
Keep one shipped binary with distinct command and daemon modules. Runner code owns Docker orchestration and local service state; CLI code owns prompts, local commit discovery, snapshot upload, and log rendering.
Control-path resetcli/src/repo_config.rs · scope-domain repo_config/repo_visibility · Git import/review
Move the repository-config worktree mirror and sync base under git rev-parse --git-path scope. Delete the broad /.scope/ ignore/reservation and any assumption that all .scope/* paths are interchangeable. Allow only validated tracked run YAML; keep config/control data private; reject unknown paths. Cover projection, import, review tree, dirty filtering, clone, init, push, and run.
Trusted worker boundaryworker/ · crates/scope-git-process
Do not add repository job execution to the existing worker, which holds database and object-store authority. The process helper may invoke Git or Docker tooling, but timeout handling alone is not a sandbox.
Web surfacesweb/src/features/runs/ · runners/
Add minimal repository rows for current/recent runs, log detail, cancel/rerun, runner name/status/version, and last heartbeat. Avoid dashboard cards; use the existing repository section and row language.

Verification gates

The feature is complete only when remote execution, privacy, restart recovery, and destructive cleanup are proven end to end.

Runner installation, device auth, systemd start, reboot reconnect, and uninstall are exercised on Linux
A developer machine triggers a job on a distinct runner machine with no direct network route
Unknown local commits upload immutable snapshots without moving repository main
Dirty working-tree changes never enter a run without first becoming part of a commit
Public execution snapshots contain no private path, blob, commit, or workflow-only control data
Workflow tag resolution records and executes one immutable container image digest
Two runners racing to claim the same run produce exactly one active attempt
Stale heartbeat, log, and completion calls cannot mutate a newer attempt
Runner loss before container start requeues; loss after start becomes terminal Lost
Cancellation kills the whole container and leaves no workspace or process behind
CPU, memory, PID, timeout, source-size, log-size, and monitored free-space limits fail predictably; hard disk quotas are claimed only when doctor proves driver support
Invalid push workflow reports a check error without rolling back the accepted push
Revoking a repository grant stops new claims immediately and preserves historical results
Runner jobs receive no database URL, object-store key, human session, Docker socket, or host mount
Desktop/mobile run views and live logs are visually verified in the running app
Every PR passes fmt, clippy, Rust tests, generated-contract checks, web tests, and targeted E2E
13

Risks that change implementation

High
Infrastructure compromise
Repository code escapes and reaches Scope credentials.
Separate runner process and credential plane; job container receives no infrastructure secret or Docker socket; never execute in the trusted worker.
High
Private-source leak
Public run receives a raw private commit or reusable clone token.
First-class audience-bound snapshot identity, content-addressed bundles, attempt-only source token, and negative object/history tests.
High
Duplicate side effects
Lease recovery reruns a script that already deployed or published.
Separate Run and Attempt; only pre-start lease loss auto-requeues; started failure becomes Lost and requires explicit user retry.
High
Host compromise from public code
A contribution exploits the shared container kernel or probes the LAN.
No automatic public-contribution jobs in V1. Later add approval, untrusted runner profile, network restrictions, and VM/microVM isolation.
Medium
Runner version skew
Old daemon misinterprets a new job protocol.
Compiled versioned job schema, minimum-compatible version in poll response, atomic one-command updates, and server refusal before claim.
Medium
Disk and log exhaustion
A job fills the runner or control plane before timeout.
Bound source, writable layer, temp space, log chunk, total log, artifact, and retained-run sizes; cleanup reconciliation after restart.
Medium
Tracked .scope confusion
Existing config-mirror assumptions conflict with versioned run files.
Destructive move under the resolved per-worktree Git path, exact allow/private/reject policy, and CLI tests for init/clone/push/run.

Deliberately not in V1

These are deferred products, not extension points to half-build in the initial implementation.

No Scope-hosted runners or paid compute
No Windows, macOS, Linux/arm64, Kubernetes, GPU scheduling, or multi-architecture matrices
No GitHub Actions compatibility, marketplace actions, reusable workflows, or expression language
No workflow DAGs, parallel jobs, service containers, cron, or deployment environments
No repository, organization, or environment secrets
No shared dependency caches or general build artifacts
No automatic public-contribution execution
No claim that Docker is a hostile multi-tenant VM boundary
No automatic retry after user code has started
No runner-to-runner or developer-to-runner networking
No backwards-compatible .scope layout or migration shim
No speculative runner groups or label scheduler before exact-name and any routing prove insufficient
